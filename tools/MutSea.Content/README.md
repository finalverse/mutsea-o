# MutSea Starter Library build contract v0.1

The offline validator checks package identity/version, rights/provenance, semantic entities/relationships, exact dependency manifests, safe payload paths, hashes and declared development budgets. It never fetches dependencies, extracts archives, executes scripts, assigns world ownership or provisions accounts/worlds. Validated bytes are not a claim of visual quality, runtime compatibility or legal review.

Run `python3 -m unittest discover -s tools/MutSea.Content -v` and `python3 tools/MutSea.Content/validate.py /absolute/package/package.json`. The Python `validate()` API accepts an explicit offline catalog mapping `(package_id, version)` to a manifest path. Dependency pins use the SHA-256 of exact manifest bytes. No version ranges or implicit latest resolution.

All packages require `schema_version: 1`, `package_id`, exact three-part `version`, `kind`, title/author/publisher, license, nonempty provenance, dependencies, files, nonempty semantic entities, budget and definition. Kind is asset/prefab/building/place/world/avatar/outfit/experience/environment. Semantics use package-local IDs; runtime instance IDs and permissions are assigned by MutSea. Ownership must be `inherit_instance_owner`. Affordances describe proposed interactions, not executable capabilities.

`WorldTemplate` is a world package with finite spawn points and composed terrain/environment/place dependencies. `AvatarTemplate` is an avatar package with required shape/skin/hair/eyes/outfit slots; those declarations do not themselves prove that appearance assets resolve. `OutfitTemplate` is an outfit package with wearable/attachment components. `AssetPackage` is the generic payload form. `ExperiencePackage` composes world/agent/workflow definitions. The initial validator checks the shared build envelope and required world/avatar fields; detailed slot/integration/runtime validation and provisioning are Phase 4B.1 work.

Definitions compose at asset/prefab/building/place/neighborhood/community/city/world scales, in meters/Z-up authoring coordinates. Export format coordinates are encoded by the exporter. File entries contain relative POSIX path, SHA-256, exact bytes and role (authoring/runtime/preview/metadata/license). No symlinks or traversal. Runtime representation is required. Rights must be from the reviewed identifier set; CC-BY requires attribution. This identifier check is not legal counsel or proof that an external license was actually obtained.

The shared contract is implemented in this build tool rather than the legacy scene-object structure. Blender embeds matching local semantic names in its objects. A future trusted server adapter must independently validate payload formats, geometry counts, permissions and dependencies before an approved transaction. Manifest declarations cannot authorize arbitrary UI extensions, workflows, scripts, commerce or server integration.

## Genesis avatar meshes

`verify_avatar_mesh.py <source package> <compiled dir>` decodes a compiled `avatar.llmesh` independently, following the viewer sources (`LLMeshHeader`, `LLMeshSkinInfo`, `llvolume.cpp` weights). It re-skins the rest pose with the viewer's joint-override chain (pelvis pinned to the root) and requires agreement with the authored glTF within 0.2 mm. `test_avatar_compile.py` runs `MutSea.AvatarCompile` rejection cases when `AVATAR_COMPILE_DLL`, `AVATAR_PACKAGE`, `VIEWER_SKELETON` and `DOTNET` are set; otherwise it is skipped.
